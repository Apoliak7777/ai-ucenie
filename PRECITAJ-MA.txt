Nasadenie Workera (raz) — čo je na Alexovi a čo spraví Claude
--------------------------------------------------------------
  1. Alex: účet na dash.cloudflare.com (zadarmo, mail + heslo).
  2. Claude spustí `npx wrangler login`; Alexovi sa otvorí prehliadač, klikne Allow.
  3. Claude:  npx wrangler d1 create ai-ucenie          → database_id do worker/wrangler.toml
              npx wrangler secret put ADMIN_HESLO -c worker/wrangler.toml   (heslo do /admin)
              npm run api:deploy                        → vypíše https://ai-ucenie.<účet>.workers.dev
              tú adresu zapísať do index.html a admin/index.html (premenná API) a pushnúť
  4. Alex: heslo schránky info@aiucenie.online do Workera, aby odchádzali potvrdenia:
              npx wrangler secret put SMTP_HESLO -c worker/wrangler.toml   (zadá ho v termináli)
              alebo dash.cloudflare.com → Workers & Pages → ai-ucenie → Settings → Variables and Secrets
Tabuľku v D1 si Worker vytvorí sám pri prvom dopyte. Log: npm run api:logs (alebo dashboard →
Workers & Pages → ai-ucenie → Logs). Repo môže zostať public — heslá sú len v Cloudflare, v repe
nie sú nikde (ani heslo do /admin).

Rezervácie vidíš na https://aiucenie.online/admin/: po zadaní hesla meno, mail, telefón, balík,
poznámka, kedy prišla; tlačidlo Zmazať uvoľní termín späť do ponuky. Stránka je mimo Googlu
(robots.txt + noindex). Zmena hesla: npx wrangler secret put ADMIN_HESLO -c worker/wrangler.toml

Lokálne skúšanie (rovnaké rozloženie ako naostro): npm install, worker/.dev.vars podľa
worker/.dev.vars.vzor, npm run api:dev (Worker na 8787) + python -m http.server 8791 (statika),
otvoriť http://127.0.0.1:8791/ — stránka aj /admin si Worker na 8787 nájdu samy.

Alternatíva, keby sa niekedy celá stránka sťahovala na Cloudflare Pages (functions/ sú na to
pripravené): apex doména musí mať DNS na Cloudflare (nameservery), potom Pages + D1 binding DB
+ tajomstvá SMTP_HESLO a ADMIN_HESLO; v index.html a admin/index.html dať API = "" (rovnaký origin).
Záloha na vlastný VPS: tá istá logika v Pythone v server/ (README tam).
Stará adresa ai.apoliak.online sa už nepoužíva (v DNS apoliak.online mieri na VPS, kde pre ňu
nič nebeží; dá sa zmazať alebo presmerovať).

Kde si upravíš termíny
----------------------
V index.html, na začiatku <script> úplne dole v súbore:

  PLAN        časy podľa dňa v týždni (1 = pondelok ... 6 = sobota, 0 = nedeľa)
              Po až Pi od 15:00, časy idú po 70 minútach = 60 min hodina + 10 min pauza
              (15:00, 16:10, 17:20, 18:30, 19:40). Víkend prázdny.
  OBSADENE    obsadené termíny vo formáte "2026-07-28 9:00"
  POCET_DNI   koľko dní s voľnými termínmi sa ponúkne
  MOJ_MAIL    kam chodia rezervácie

Odosielanie rezervácií
----------------------
Tam istá časť skriptu:

  API             adresa Workera (https://ai-ucenie.<účet>.workers.dev); na 127.0.0.1 alebo
                  localhoste sa automaticky použije http://127.0.0.1:8787 (npm run api:dev)
  ENDPOINT        API + "/api/rezervacia": rezervácia sa zapíše do D1, termín ostane obsadený
                  pre všetkých, mne príde mail a klientovi potvrdenie. Prázdne = klientovi sa
                  otvorí jeho mail s vyplnenou rezerváciou (ak nemá mailový program, stratí sa).
  OBSADENE_URL    API + "/api/obsadene" — odtiaľ si widget pri načítaní stiahne obsadené termíny,
                  takže ich nevidí ani ďalší návštevník
  ENDPOINT_EXTRA  polia navyše, keby sa ENDPOINT nasmeroval na externú službu

Keď si termín medzitým vzal niekto iný, Worker vráti 409 a widget človeka vráti na výber
s hláškou — NEpresmeruje ho na mail.
Keď Worker neodpovedá vôbec, web ukáže chybu a otvorí mail ako záložnú cestu.
Formulár má aj skrytú pascu na roboty (pole "web") — ak ho niekto vyplní, rezervácia sa
neodošle (Worker to ticho zahodí tiež).
Worker prijíma dopyty len z aiucenie.online, www.aiucenie.online, apoliak7777.github.io
a z localhostu (CORS: POVOLENE_ORIGINY v lib/rezervacie.js).

Termíny dohodnuté mimo stránky (telefón, mail) dopíš do OBSADENE v index.html, Worker o nich
nevie. POZOR: keby sa ENDPOINT niekedy presmeroval na cudziu službu, doplň ju do
ochrana-udajov.html do sekcie "Kde údaje sú" ako sprostredkovateľa.
